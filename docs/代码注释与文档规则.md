# 代码注释与文档规则

## 目标

本项目是 `zjj-virtual-arcade-controller` 的 Three.js 游戏示例，后续会继续加入角色、武器、子弹、丧尸、升级规则等内容。为了避免逻辑分散后难以维护，新增代码需要同步留下必要注释和文档说明。

## 注释规则

- 对资源映射写注释：例如武器等级和 `blaster-a` 到 `blaster-r` 的对应关系。
- 对游戏规则写注释：例如击杀数如何换算武器等级、子弹模型如何按等级选择。
- 对异步模型加载写注释：例如为什么保留 fallback 几何体、为什么需要防止旧加载结果覆盖新状态。
- 不写无意义注释：例如“创建变量”“调用函数”这类从代码本身已经能看出的内容。

## 文档规则

以下改动需要同步更新 `docs/`：

- 新增或调整游戏机制。
- 新增模型、贴图、音效等资源映射。
- 调整玩家、丧尸、武器、子弹等核心实体职责。
- 改动控制器输入、按钮含义或 HUD 展示。

文档应说明：

- 改动解决什么问题。
- 核心规则是什么。
- 涉及哪些主要文件。
- 后续如果要扩展，应该从哪里改。

## 当前掉落与武器等级规则

当前游戏设定 18 级武器，武器等级不再由击杀数直接提升，而是通过拾取弹匣获得经验：

- 最高 18 级。
- `Lv.1` 对应 `blaster-a.glb`。
- `Lv.18` 对应 `blaster-r.glb`。
- 子弹模型只有 4 种，所以按等级循环使用。
- 僵尸死亡后有 50% 概率掉落装备。
- 掉落装备中 60% 是弹匣，40% 是血包。
- 弹匣使用 `clip-small.glb`，竖立显示，拾取后增加 1 点武器经验。
- 血包使用 `Previews/target-fragment-small.png` 作为贴片图标，拾取后恢复 20 点生命值。
- `Lv.1 -> Lv.2` 需要 3 点经验，之后每升一级需求增加 1 点经验。

## 当前数值成长规则

武器等级会影响伤害、射击间隔和子弹速度：

- 武器伤害：`15 + (等级 - 1) * 2`。
- 射击间隔：从 `0.65s` 随等级降低，最低 `0.35s`。
- 子弹速度：`9 + (等级 - 1) * 0.18`。
- 每个弹匣固定 13 发子弹，打空后自动进入 2.5 秒换弹。
- 换弹期间角色仍然可以移动和瞄准，但枪不会生成新子弹；重新开始或进入新房间时弹匣重置为满弹。
- 子弹数量显示在底部 HUD，换弹倒计时同步显示在玩家头顶的 Three.js Sprite 标签上；非换弹状态不显示头顶标签。

僵尸强度会随着存活时间和武器等级提升：

- 僵尸血量：`75 + 存活分钟数 * 18 + 武器等级 * 5`，最高 `260`。
- 僵尸速度：`1.4 + 存活分钟数 * 0.08`，最高 `2.1`。
- 刷新间隔：从 `1.6s` 随存活时间降低，最低 `0.65s`。
- 场上僵尸数量上限：15 个，达到上限后暂停生成，直到有僵尸被击杀。

## 当前物理碰撞规则

Rapier 负责角色和地图边界的基础碰撞：

- 物理世界关闭重力，游戏仍然锁定在 X/Z 平面移动。
- 玩家和僵尸都使用 capsule 碰撞体，移动通过 `KinematicCharacterController` 计算。
- 地图四周使用 4 个静态 box collider 作为边界墙。
- 地图障碍物使用后端 `maps.config` 中的手写 box collider，详见 `docs/地图组件碰撞配置.md`。
- 地图视觉对象和地图 collider 由 `src/game/map/MapManager.ts` 统一创建和卸载，`GameWorld` 不再直接写死具体地图配置。
- 子弹命中仍然使用 `CollisionSystem` 的 2D 距离检测，不迁移到 Rapier。
- 僵尸接触玩家扣血仍然使用 `CollisionSystem` 的 2D 距离检测，但会额外加上 `GAME_CONFIG.zombieContactPadding`。Rapier 会把两个 capsule 挡在刚好不重叠的位置，所以伤害触发需要保留一点贴身余量。
- 掉落物拾取仍然使用 `DropSystem` 的拾取半径检测，不创建刚体。
- `GAME_CONFIG.showPhysicsDebug` 是开发调试开关，打开后用 Rapier `debugRender()` 显示真实 collider 线框，默认关闭。

## 当前 HUD 规则

底部中间 HUD 分成两层：

- 上层信息面板只显示击杀、时间、僵尸数量、武器等级和状态。
- 下层状态条显示玩家血量和武器经验。
- 血量是红色长条，文本居中显示当前血量。
- 武器经验是蓝色长条，文本居中显示当前经验和升级所需经验。

## 当前角色尺寸规则

玩家和僵尸的可视模型、简易 fallback 模型和 Rapier capsule 碰撞体统一在 `GAME_CONFIG` 里配置，避免人物缩小后仍然保留过大的碰撞体积。

- 玩家模型目标高度为 `playerVisualHeight`，僵尸模型目标高度为 `zombieVisualHeight`。
- 玩家碰撞体使用 `playerRadius` 和 `playerColliderHalfHeight`，僵尸碰撞体使用 `zombieRadius` 和 `zombieColliderHalfHeight`。
- 枪械挂点、子弹出生高度和子弹出生前移距离分别使用 `playerGunMountHeight`、`playerGunMountForward`、`bulletSpawnHeight` 和 `bulletSpawnForward`，需要跟随人物尺寸一起调整。
- 僵尸血条位置根据 `zombieVisualHeight` 计算，避免角色缩小后血条穿进头部或悬得过高。

## 当前资源加载进度规则

游戏冷启动会在创建 `GameWorld` 前预加载核心资源，并在画布中间显示进度条：

- `src/game/systems/AssetLoadingProgress.ts` 负责统一收集 Three.js `LoadingManager` 事件和手动资源任务。
- `src/game/systems/preloadGameAssets.ts` 负责预加载玩家、僵尸、武器、子弹、掉落物和首张地图的模型资源。
- 进度条按“资源任务完成数”统计，不按网络字节统计。这样 FBX、GLB、贴图和动态 import 的资源都能进入同一套显示。
- 首屏只预加载当前进入地图需要的模型，不一次性加载所有后续房间，避免冷启动等待更久。
- 后续切换地图或首次出现新资源时，如果触发新的资源加载任务，会复用同一套进度状态。

## 当前瞄准与射击规则

射击不再自动锁定最近僵尸，而是跟随玩家鼠标红外线：

- `GameWorld` 监听游戏 canvas 的 `pointermove` 和 `pointerdown`，用 `THREE.Raycaster` 从相机投射到 `y=0` 地面平面，得到鼠标指向的世界坐标。
- `Gun.update()` 接收鼠标指向位置，玩家和枪朝红外线方向转向，并按当前武器射速持续发射子弹。
- 鼠标进入画布前，红外线默认指向角色当前朝向前方，避免没有指针输入时无法射击。
- 红外线只是视觉方向提示，不参与物理碰撞、子弹命中或地图射线选择。
