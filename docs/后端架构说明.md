# Go 后端架构说明

## 目标

当前后端先服务关卡编辑器，把地图配置保存为本地 JSON。目录已经按后续接数据库、登录、资源管理和更多 CRUD 的方向拆开，但第一版不改变现有接口行为。

## 分层职责

- `cmd/server`：程序入口，只负责读取配置、创建服务、启动监听。
- `internal/config`：统一读取环境变量和默认配置。
- `internal/app`：组装依赖，例如路由、存储、后续数据库连接。
- `internal/http`：HTTP 路由入口，负责挂载 `/api`、健康检查和业务 handler。
- `internal/http/middleware`：HTTP 中间件，当前只有开发期 CORS。
- `internal/maps`：地图业务的第一版模块，当前包含 handler、文件存储和请求类型。
- `internal/database`：数据库连接、迁移驱动和事务封装。当前已经预留 MySQL + GORM 连接初始化。
- `internal/domain`：领域模型。当前包含地图主表和地图版本表的 GORM 模型。
- `internal/repository`：预留数据库仓储实现。
- `internal/service`：预留业务用例层，后续放保存地图、发布地图、版本回滚等应用逻辑。
- `internal/platform`：预留跨模块基础设施，例如日志、ID、时间、对象存储客户端。
- `migrations`：数据库迁移文件。当前包含地图主表和版本表的建表脚本。
- `scripts`：预留开发、导入导出和运维脚本。
- `configs`：预留本地配置样例。

## 当前配置

默认仍然使用文件存储。数据库配置已经预留，但只有 `DB_ENABLED=true` 时才会连接 MySQL。

```bash
ADDR=:8088
MAP_DATA_DIR=data
DB_ENABLED=false
DB_DRIVER=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_NAME=zjj_game
DB_USER=root
DB_PASSWORD=
```

默认存储路径：

- 当前地图：`server/data/maps/{mapKey}.json`
- 历史版本：`server/data/versions/{mapKey}/v000001.json`

## 后续接数据库的建议路径

1. 给 `internal/maps` 抽出 `Store` 接口，让 handler 不依赖 `FileStore` 具体实现。
2. 在 `internal/repository` 增加 MySQL 版本的地图仓储。
3. 在 `migrations` 增加建表脚本。
4. 在 `internal/app` 根据配置选择 `FileStore` 或 MySQL 仓储。
5. 等数据库存储稳定后，再考虑登录、管理员权限和发布状态流转。

数据库配置细节见 `docs/数据库配置说明.md`。

这样可以保留当前文件存储作为开发兜底，同时逐步把正式数据迁到数据库。
