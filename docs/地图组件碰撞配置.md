# 地图组件碰撞配置

## 目标

地图模型和物理碰撞不要强绑定。第一版地图障碍物使用手写 box collider 配置，避免从完整 mesh 自动生成碰撞体导致性能和精度不可控。

## 文件职责

- `src/game/map/types.ts`：定义地图配置类型。
- 后端 `maps.config`：维护具体房间地图的障碍物可视配置和碰撞配置。
- `/api/maps`：提供可用地图列表和具体地图配置，地图切换弹窗和地图管理器都从这里读取。
- `src/game/map/MapManager.ts`：读取地图配置，创建/卸载 Three.js 可视障碍物和 Rapier 静态 collider。
- `src/game/systems/GameWorld.ts`：持有 `MapManager`，在场景和物理系统初始化时调用地图加载能力。

## 配置规则

`position` 和 `size` 都是 `[x, y, z]`：

- `position` 表示盒子中心点。
- `size` 表示完整宽高深，不是 half extents。
- `rotation` 表示欧拉角 `[x, y, z]`，单位是弧度；从关卡编辑器导出的 collider 默认跟随物体旋转，运行时会转换成 Rapier quaternion。
- `color` 只影响当前占位可视盒子，后续替换成真实地图模型后可以移除或保留做调试。

## 编辑器吸附

关卡编辑器的吸附开关只用于开发时摆放物体，不会写入地图配置。开启后，新放置或拖动的物体会根据启用的 box collider 在 X/Z 平面贴到附近物体边缘，并会在靠边时同步吸齐相邻边角，减少手工对齐围栏、墓碑、墙体等连续物件的成本。Y 轴高度保持当前物体设置。旋转物体会先用 collider 的世界轴向投影计算吸附范围，因此斜放物体也能避免明显重叠。

## 后续接真实地图模型

接入真实地图模型时优先保持这套结构：

- 模型只负责视觉。
- 每张 `GameMapConfig.colliders` 负责对应房间内的物理阻挡。
- 如果模型里有墙、箱子、建筑，需要手动补对应的 box collider。
- 不从完整 glb/fbx mesh 自动生成碰撞体，除非后续专门做性能和形状验证。
