# 前端路由与游戏启动说明

## 目标

前端现在把游戏和关卡编辑器拆成两个 `vue-router` 页面入口，避免刷新后总是回到游戏画面，也避免游戏页面一打开就自动开始战斗。

当前路由：

- `/`：游戏页面。
- `/editor`：关卡编辑器页面。

项目入口同时注册了 `Pinia` 和 `Element Plus`，后续可以逐步把跨页面状态放到 store，把管理型表单、弹窗和提示组件迁移到 Element Plus。

## 页面入口

顶部右侧“游戏 / 编辑器”是页面切换入口，内部通过 `RouterLink` 跳转。

切到编辑器时，地址会变成 `/editor`。刷新浏览器后仍然停留在编辑器，不会回到游戏。

切到游戏时，地址会变成 `/`。刷新浏览器后仍然停留在游戏页，但不会直接进入战斗。

## 游戏启动规则

游戏页分成两个阶段：

- 未开始：显示“开始游戏”面板，不挂载 `ZombieSurvivalGame`，Three.js 主循环不会启动。
- 已开始：点击“开始游戏”后挂载 `ZombieSurvivalGame`，开始创建场景、加载地图、生成角色和僵尸。

这样做的原因是游戏示例属于可交互页面，用户进入页面或刷新页面时应该先看到明确的开始动作，而不是直接进入战斗状态。

## 地图加载关系

游戏页进入后仍会先从后端读取地图列表。

如果后端地图为空或接口失败，“开始游戏”按钮不会出现可用战斗状态，页面会显示后端错误提示。

只有满足下面条件时才能开始：

- 地图加载完成。
- 没有地图接口错误。
- 后端至少返回一张地图。

## 控制器显示规则

虚拟摇杆、按钮、HUD 和血量/经验条只在游戏已经开始后显示。

编辑器页面不会显示游戏控制器，避免摇杆和编辑器画布抢输入。

## 文件结构

- `src/router/index.ts`：路由定义。
- `src/views/GameView.vue`：游戏页面，负责地图加载、开始游戏、HUD、控制器和游戏实例挂载。
- `src/views/EditorView.vue`：编辑器页面，负责展示关卡编辑器。
- `src/main.ts`：注册 `Pinia`、`vue-router` 和 `Element Plus`。

## 后续可优化
