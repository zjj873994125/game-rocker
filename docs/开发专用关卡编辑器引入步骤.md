# 开发专用关卡编辑器引入步骤

## 目标

新增一个只在开发阶段使用的关卡编辑器，用来快速摆放地图物件、配置碰撞体、设置玩家出生点、设置出口门和开门击杀数，并导出可接入游戏的 `GameMapConfig` 配置。

第一版编辑器不是玩家功能，也不是完整商业关卡编辑器。它的目标是减少手写地图配置的成本，让后续导入新地图模组后可以更快生成地图配置。

## 第一版定位

- 开发工具，不面向玩家。
- 放在当前项目内，不进入 npm 包能力。
- 优先支持 Kenney 墓地资源和当前占位地图配置。
- 输出配置文本，开发者手动复制到地图配置文件。
- 不接后端，不做在线保存。

- [x] 6. 支持点击放置对象

  实现从资源面板选择资源，然后点击编辑画布放置对象。

  第一版交互：

  - 选择左侧资源。
  - 点击地面。
  - 在点击位置生成对象。
  - 对象加入编辑器状态列表。

  技术建议：

  - 使用 Three.js `Raycaster` 从鼠标位置投射到地面。
  - 对象第一版可以用 box placeholder。

  验收点：

  - 点击不同位置可以生成多个对象。
  - 新对象位置和点击位置基本一致。
  - 对象能在右侧属性面板中被选中。

  已完成：

  - `EditorWorld` 新增 `setSelectedAsset()`、地面 `pointerdown` 监听和 `Raycaster` 投射逻辑。
  - 选择左侧资源后，点击 Three.js 地面会生成对象并加入编辑器场景；有模型资源时显示真实 GLB 模型，缺少模型时回退为 box placeholder。
  - 放置对象会生成 `EditorMapObject`，包含资源 id、名称、类型、位置、旋转、缩放、颜色和默认 collider 配置。
  - `LevelEditor.vue` 通过 `onObjectPlaced` 回调维护 `placedObjects`，并自动选中新放置对象。
  - 右侧属性面板会显示选中对象、对象位置、对象数量和已放置对象列表。
  - `corepack pnpm run build` 已通过。

- [x] 8. 支持 collider 配置

  在属性面板中给选中对象配置 collider。

  第一版规则：

  - 每个对象最多一个 box collider。
  - 可以打开/关闭 collider。
  - 可以编辑 collider 的 `position` 和 `size`。
  - 可选显示 collider 线框。

  验收点：

  - 对象可以生成 collider 配置。
  - collider 线框和对象大致对齐。
  - 导出配置时能包含 `colliders`。

  已完成：

  - `EditorWorld` 新增 collider 线框预览，每个对象最多显示一个 box collider，并在关闭 collider 时同步移除线框。
  - `LevelEditor.vue` 右侧属性面板新增“启用碰撞体”、碰撞体位置 X/Y/Z、碰撞体尺寸 X/Y/Z 配置。
  - 对象位置变化时会继续同步默认 collider 位置；也可以在属性面板里单独微调 collider，方便后续真实模型和物理碰撞体分离。
  - 对象旋转变化时，collider 线框会跟随同一份旋转；导出后运行时 Rapier 静态 box collider 也会使用该旋转。
  - 编辑视口新增吸附开关；开启后，放置或拖拽物体时会按启用的 collider 在 X/Z 平面自动贴到相邻物体边缘，并尽量同步对齐相邻边角，减少物体互相重叠和边角手工微调。
  - collider 尺寸会限制为最小 `0.1`，避免生成无效尺寸导致线框和后续 Rapier 配置失真。
  - 当前编辑器状态中的 `EditorMapObject.collider` 已包含导出 `GameMapConfig.colliders` 所需的位置、尺寸和启用状态；正式导出文本会在步骤 10 接入。
  - `corepack pnpm run build` 已通过。

- [x] 9. 支持出生点和门配置

  在编辑器里支持设置玩家出生点和出口门。

  第一版交互：

  - 一个按钮用于“设置出生点”，点击地面后更新 `spawnPoint`。
  - 一个按钮用于“添加出口门”，点击地面后生成门。
  - 右侧属性面板可以编辑门的 `targetMapId`、`targetSpawnId`、`interactionDistance`、`size`。
  - 可以设置当前地图 `requiredKills`。

  验收点：

  - 出生点可视化。
  - 门可视化。
  - 门配置能导出到 `doors`。

  已完成：

  - `EditorWorld` 新增编辑模式：放置对象、设置出生点、添加门。点击地面会根据当前模式更新对应配置。
  - 出生点使用绿色地面圆环和向上标记可视化，支持点击地面更新；只有切到“设置出生点”模式时，右侧属性面板才显示出生点 X/Y/Z 输入。
  - 门使用半透明蓝色 box 可视化，添加后会进入门列表，并支持编辑位置、尺寸、目标地图 ID、目标出生点 ID 和交互距离。
  - `LevelEditor.vue` 右侧属性面板新增地图 ID、地图名称、开门击杀数、出生点配置和出口门配置。
  - 当前编辑器状态已经维护 `spawnPoint`、`requiredKills` 和 `doors`，正式生成 `GameMapConfig.doors` 的文本导出会在步骤 10 接入。
  - 编辑器已补充基础操作能力：选中对象或门后可以在画布中拖拽移动；右侧属性面板可以删除选中对象或选中门。
  - 编辑视口已接入 `OrbitControls`，支持滚轮缩放和右键/触控板平移地图镜头，并支持通过 WASD 旋转镜头：A/D 左右环绕，W/S 调整俯仰；编辑器自己的放置和选中逻辑只响应左键，避免右键平移时误放置对象。
  - 画布拖拽会保留鼠标命中点和物体中心的偏移，并带有 5px 启动阈值；纯点击只负责选中，选中物体时不会把物体中心瞬间吸附到鼠标位置。
  - `corepack pnpm run build` 已通过。

## 第一版不做

- 不做在线保存。
- 不做后端接口。
- 不做多人协作。
- 不做撤销/重做。
- 不做复杂地形雕刻。
- 不做自动从模型生成复杂 collider。
- 不做玩家可见入口。
- 不做完整资源浏览器。
- 不做关卡脚本系统。

## 推荐执行顺序

先做步骤 1 到 5，把编辑器页面和 Three.js 画布跑起来；再做步骤 6 到 9，让对象、碰撞体、出生点和门可以编辑；最后做步骤 10 到 12，完成导出、回接验证和使用文档。
