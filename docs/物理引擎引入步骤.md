# Rapier 物理引擎引入步骤

## 目标

在加入地图模型组件前，引入 Rapier 作为角色和地图障碍物的碰撞系统。第一阶段只处理玩家、僵尸、地图边界和地图障碍物，不把子弹命中、掉落物拾取、UI 状态迁移到物理引擎里。

## 步骤清单

- [x] 1. 安装 Rapier 依赖

  安装 `@dimforge/rapier3d-compat`。

  验收点：

  - `package.json` 出现 Rapier 依赖。
  - `corepack pnpm install` 后锁文件更新。
  - `corepack pnpm run build` 可以通过。

- [x] 2. 新增 `PhysicsWorld.ts`

  在 `src/game/systems/PhysicsWorld.ts` 里封装 Rapier 初始化和基础 API。

  第一版需要包含：

  - `init()`：初始化 Rapier。
  - `step()`：推进物理世界。
  - `createPlayerBody()`：创建玩家 capsule/cylinder 碰撞体。
  - `createZombieBody()`：创建僵尸 capsule/cylinder 碰撞体。
  - `removeBody()`：删除刚体和碰撞体。
  - `syncObject()`：把刚体位置同步回 Three.js `Object3D`。

  验收点：

  - 不改变现有游戏表现。
  - 可以创建和销毁刚体。
  - build 通过。

  已完成：

  - 新增 `src/game/systems/PhysicsWorld.ts`，封装 Rapier 初始化、无重力物理世界、玩家/僵尸 capsule 刚体、静态 box collider、刚体删除和 Three.js 对象位置同步。
  - 当前文件尚未接入 `GameWorld`，所以不会改变现有游戏表现。

- [x] 3. 改造玩家移动

  玩家不再直接写 `group.position` 作为最终位置，而是计算目标位置后交给物理系统。

  建议做法：

  - `Player.update()` 只计算移动方向、速度、朝向和动画状态。
  - `GameWorld` 把玩家目标位移交给 `PhysicsWorld`。
  - 物理 `step()` 后同步玩家 `group.position`。

  验收点：

  - 摇杆仍然能控制玩家移动。
  - 玩家不会穿过地图边界 collider。
  - 玩家动画和朝向仍然正常。

  已完成：

  - `Player.update()` 改为计算下一帧目标位置、朝向和动画状态，不再直接写最终位置。
  - `GameWorld` 初始化 `PhysicsWorld` 和玩家 capsule 刚体，运行中把玩家目标位置交给 Rapier character controller，再同步回 Three.js 角色模型。
  - 当前还没有接入地图边界 collider，所以“不能穿过地图边界”会在步骤 5 完成后最终验证。

- [x] 4. 改造僵尸移动

  僵尸追踪玩家时不再直接写最终位置，而是交给物理系统处理移动和碰撞。

  验收点：

  - 僵尸仍然会追玩家。
  - 僵尸碰到玩家时不再直接穿过去。
  - 僵尸和僵尸之间不会完全重叠。
  - 接触伤害逻辑仍然生效。

  已完成：

  - `Zombie.update()` 改为计算下一帧目标位置、朝向、受击闪烁和动画状态，不再直接写最终位置。
  - `GameWorld` 为每个僵尸维护 `Zombie -> PhysicsBodyHandle` 映射，生成、死亡、重置时同步创建和删除 Rapier capsule 刚体。
  - 玩家和僵尸现在统一提交目标位移，统一执行 `PhysicsWorld.step()`，再统一同步回 Three.js 模型。
  - 已验证僵尸可以继续刷新、追踪玩家、被子弹击杀；接触阻挡效果会在地图边界和障碍 collider 接入后继续验证。

- [x] 5. 接入地图边界 collider

  用 Rapier 静态 collider 替代或补充当前视觉边界。

  第一版边界可以是 4 个长方体：

  - 上边界
  - 下边界
  - 左边界
  - 右边界

  验收点：

  - 玩家不能走出地图。
  - 僵尸不能穿出地图。
  - 摄像机跟随不受影响。

  已完成：

  - `GameWorld` 在 `PhysicsWorld` 初始化后创建 4 个静态 box collider 作为地图边界墙。
  - 玩家移动已移除旧的手动 `clampToMap` 限制，边界阻挡由 Rapier collider 接管。
  - 僵尸生成增加场上数量上限，当前暂定最多 15 个。

- [x] 6. 设计地图组件碰撞配置

  新增地图模型组件时，不直接从完整 mesh 自动生成碰撞体。第一版使用手写配置。

  建议数据结构：

  ```ts
  type MapColliderConfig = {
    position: [number, number, number]
    size: [number, number, number]
  }
  ```

  验收点：

  - 地图模型可以单独加载。
  - 地图障碍物 collider 可以跟随配置生成。
  - 玩家和僵尸不能穿过障碍物。

  已完成：

  - 新增 `src/game/map/types.ts` 和房间地图配置文件，地图障碍物 collider 使用手写配置维护。
  - `GameWorld` 根据地图配置创建 Three.js 占位障碍物和 Rapier 静态 box collider。
  - 新增 `docs/地图组件碰撞配置.md`，说明后续真实地图模型和碰撞配置的分离方式。

- [x] 7. 保留现有子弹和掉落逻辑

  子弹命中仍然使用当前圆形距离检测，掉落物拾取仍然使用拾取半径。

  暂不迁移原因：

  - 子弹速度高，刚体碰撞容易出现穿透和事件处理复杂度。
  - 掉落物只需要拾取范围，不需要刚体模拟。

  验收点：

  - 子弹仍然能打中僵尸。
  - 弹匣和血包仍然可以拾取。
  - 武器升级、回血、HUD 都不受影响。

  已完成：

  - `CollisionSystem` 继续使用子弹和僵尸的 2D 距离检测处理命中和击杀。
  - `DropSystem` 继续使用玩家和掉落物的拾取半径处理弹匣经验、血包回血。
  - 代码注释和 `docs/代码注释与文档规则.md` 已明确这两类逻辑暂不迁移到 Rapier。

- [x] 8. 可视化调试开关

  增加一个开发用开关，显示玩家、僵尸、地图障碍物 collider 的范围。

  验收点：

  - 开关关闭时不影响正式画面。
  - 开关开启时可以看到 collider 大致范围。
  - collider 和模型位置基本对齐。

  已完成：

  - 新增 `GAME_CONFIG.showPhysicsDebug` 开关，默认关闭。
  - `PhysicsWorld` 暴露 Rapier `debugRender()` 数据。
  - `GameWorld` 在开关打开时用 Three.js `LineSegments` 渲染真实 collider 线框。

- [x] 9. 最终验证

  完成第一版 Rapier 接入后，需要验证：

  - `corepack pnpm run build` 通过。
  - 玩家不能穿地图边界。
  - 玩家不能穿地图障碍物。
  - 僵尸不能穿玩家和主要障碍物。
  - 子弹、掉落、武器升级和 HUD 仍然正常。

  已完成：

  - `corepack pnpm run build` 通过。
  - 浏览器运行验证通过：游戏正常渲染，HUD 正常更新，击杀数增长，僵尸数量上限稳定在 15。
  - 地图边界、地图障碍物、玩家和僵尸都已经接入 Rapier collider；运行截图中可见障碍物和角色碰撞堆叠。
  - 子弹命中、掉落物出现、血量和武器经验条未受 Rapier 接入影响。
  - 已知残留：Rapier compat 包会输出初始化参数 deprecated warning，不影响当前运行。

## 第一阶段不做

- 不做完整 mesh 自动碰撞体生成。
- 不做子弹刚体化。
- 不做掉落物刚体化。
- 不做 ragdoll、击飞、复杂物理动画。
- 不引入重力和跳跃，角色仍然固定在 X/Z 平面移动。

## 推荐执行顺序

先做步骤 1 到 5，让现有空地图具备基础碰撞体积；再做地图模型组件和步骤 6。这样地图模型进来时，只需要补 collider 配置，不需要重新改角色移动架构。
