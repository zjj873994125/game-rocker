# 多地图房间与开门切图开发步骤

## 目标

把当前单地图生存玩法改造成可扩展的“房间关卡”架构。第一阶段先不追求大量地图内容，重点是搭好地图配置、地图加载/卸载、通关开门、进入下一房间、地图切换弹窗这些基础能力。

第一版规则：

- 每张地图是一个独立房间。
- 当前房间击杀数达到配置要求后，出口门开启。
- 玩家靠近开启的门并触发进入逻辑后，加载目标房间。
- 进入新房间时按“完全新关卡”处理：血量、武器等级、经验、击杀数、计时、僵尸、子弹、掉落全部重置。
- 先用墓地资源做第一张地图；如果资源足够，可以用同一套墓地资源临时做第二张变体地图验证切换链路。
- 地图切换弹窗作为演示/调试入口，可以直接选择地图。

## 步骤清单

- [x] 1. 扩展地图配置类型

  修改 `src/game/map/types.ts`，把当前只支持 `colliders` 和 `props` 的配置扩展成房间地图配置。

  需要新增或调整：

  - `GameMapConfig.id`：地图唯一标识。
  - `GameMapConfig.name`：地图中文名称，用于弹窗和 HUD 展示。
  - `GameMapConfig.spawnPoint`：玩家进入地图后的出生点。
  - `GameMapConfig.requiredKills`：当前房间开门需要的击杀数。
  - `GameMapConfig.doors`：当前地图的门配置。
  - `MapDoorConfig`：门的位置、尺寸、目标地图、目标出生点、交互距离。

  验收点：

  - 类型能表达“墓地入口 -> 下一个房间”的关系。
  - 旧的障碍物 collider 和占位 prop 配置仍然可以迁移到新类型里。
  - `corepack pnpm run build` 不应因为类型定义报错。

  已完成：

  - `src/game/map/types.ts` 新增 `MapDoorConfig`，并为 `GameMapConfig` 补充 `id`、`name`、`spawnPoint`、`requiredKills`、`doors`。
  - `src/game/map/arenaMap.ts` 已按新类型补齐墓地入口的基础房间信息和出口门配置。
  - `corepack pnpm run build` 已通过。

- [x] 2. 拆分地图配置文件

  旧阶段曾计划新增地图配置文件，把当前 `arenaMap.ts` 的占位地图迁移成房间地图。当前地图主数据已经迁移到后端数据库。

  当前结构：

  ```text
  后端 maps 表
  后端 map_versions 表
  前端 src/game/map/types.ts
  前端 src/game/map/MapManager.ts
  ```

  当前规则：

  - 地图配置保存在后端 `maps.config`。
  - 历史版本保存在后端 `map_versions.config`。
  - 前端通过 `/api/maps` 读取地图列表和具体地图配置。

  如果暂时只做一张地图：

  - 仍然保留 `maps.ts`。
  - 第二张地图可以先用同一套墓地资源做临时变体，后续新资源导入后替换配置。

  验收点：

  - 地图配置不再写死在 `GameWorld.ts`。
  - 至少有一张可加载地图。
  - 如果做两张地图，第一张门的 `targetMapId` 能指向第二张。

  已完成：

  - 旧阶段曾新增本地地图文件维护墓地入口和墓穴区。
  - 当前地图主数据已经迁移到后端数据库，不再通过本地 `maps.ts` 注册地图。
  - 删除旧的 `src/game/map/arenaMap.ts`，`GameWorld` 暂时改为从 `defaultGameMapConfig` 读取默认地图。
  - 同步更新 `docs/地图组件碰撞配置.md`、`docs/代码注释与文档规则.md`、`docs/物理引擎引入步骤.md` 中的旧地图配置路径。
  - `corepack pnpm run build` 已通过。

- [x] 3. 新增 `MapManager`

  新增 `src/game/map/MapManager.ts`，专门管理地图生命周期，避免继续把地图逻辑塞进 `GameWorld.ts`。

  职责：

  - 保存当前地图配置。
  - 加载地图视觉对象。
  - 创建地图障碍物 collider。
  - 卸载旧地图对象和旧 collider。
  - 判断当前地图是否已通关。
  - 根据玩家位置判断是否靠近可进入的门。
  - 提供地图列表给弹窗使用。

  第一版视觉对象可以继续使用当前 box 占位物；墓地真实模型加载可以放到后续步骤，不阻塞架构。

  验收点：

  - `GameWorld` 可以通过 `MapManager.loadMap(mapId)` 切换地图。
  - 切换地图时旧地图模型和旧 collider 会被清理。
  - `MapManager` 内部有必要注释，说明为什么地图模型和碰撞体分开维护。

  已完成：

  - 新增 `src/game/map/MapManager.ts`，集中管理当前地图、地图列表、地图加载、地图卸载、地图 prop、地图 collider 和门距离判断。
  - `MapManager.loadMap(mapId)` 已支持根据地图 `id` 切换当前地图，并可在传入 `PhysicsWorld` 时同步创建新地图 collider。
  - `MapManager.unloadMap()` 会移除旧地图 Three.js 对象，并在传入 `PhysicsWorld` 时删除旧地图 collider。
  - `MapManager.findEnterableDoor()` 已提供“击杀达标并靠近门”的判断能力，后续第 5、6 步接入实际通关和进入房间逻辑。
  - `corepack pnpm run build` 已通过。

  验收点：

  - 游戏启动后仍然能正常进入第一张地图。
  - 玩家、僵尸和地图障碍物碰撞仍然正常。

- [x] 5. 接入通关开门规则

  在 `GameWorld` 或 `MapManager` 中根据当前击杀数判断房间是否通关。

  第一版规则：

  - `kills >= currentMap.requiredKills` 后，当前地图出口门开启。
  - 未通关时门不可进入。
  - 通关后靠近门可以进入下一张地图。

  门的表现第一版可以先做轻量效果：

  - 未开启：门模型或占位门为暗色。
  - 已开启：门模型或占位门变亮。
  - 门附近可以有简单提示，但不要遮挡游戏主画面。

  验收点：

  - 击杀数未达标时不能进门。
  - 击杀数达标后门状态变化。
  - 门状态不会影响现有射击、掉落和物理碰撞逻辑。

  已完成：

  - `MapManager` 新增 `updateDoorState(kills)`，会根据当前地图 `requiredKills` 判断门是否开启。
  - 占位门未开启时使用暗色材质，击杀达标后改为绿色并增加轻微自发光，后续替换真实门模型时继续复用这个状态入口。
  - `GameWorld` 在运行帧和重置时都会同步刷新门状态。
  - `MapManager.findEnterableDoor()` 已经保证未通关时不会返回可进入门，第 6 步会接入实际进入房间交互。
  - `corepack pnpm run build` 已通过。

- [x] 6. 增加进入房间交互

  设计玩家进入门的触发方式。

  第一版建议：

  - 玩家靠近已开启的门后，按手柄按钮进入下一张地图。
  - 如果暂时没有合适按钮，也可以先用地图切换弹窗验证切换链路，再接按钮。

  进入下一张地图时执行完整关卡重置：

  - 清空所有僵尸。
  - 清空所有子弹。
  - 清空所有掉落物。
  - 玩家血量恢复默认值。
  - 武器等级和经验重置。
  - 击杀数归零。
  - 计时归零。
  - 刷新器重置。
  - 玩家移动到目标地图出生点。

  验收点：

  - 从第一张地图进入第二张地图后，HUD 数值全部按新关卡重置。
  - 不会残留上一张地图的僵尸、子弹、掉落物或 collider。
  - 玩家出生位置正确。

  已完成：

  - `GameWorld` 新增 `tryEnterDoor()`，在运行状态下按下 A/冲刺键时检测是否靠近已开启的门。
  - 复用 `MapManager.findEnterableDoor()`，未达到当前地图 `requiredKills` 时不会进入下一房间。
  - 进入下一房间时调用 `MapManager.loadMap(targetMapId, { physics })`，会卸载旧地图对象和旧地图 collider，并加载目标地图对象和 collider。
  - 抽出 `resetLevelProgress()`，进入新房间和重新开始都会清空僵尸、子弹、掉落物，重置血量、武器等级、经验、击杀数、计时和刷新器，并把玩家放到当前地图 `spawnPoint`。
  - 操作说明已补充“门开启后靠近出口按 A 进入下一房间”。
  - `corepack pnpm run build` 已通过。

## 第一阶段不做

- 不做完整关卡编辑器。
- 不做地图无缝流式加载。
- 不做自动从复杂模型生成 mesh collider。
- 不做复杂开门动画。
- 不做钥匙、剧情、任务系统。
- 不做多个地图资源包的最终美术定稿。

## 推荐执行顺序

先做步骤 1 到 4，把多地图架构搭起来；再做步骤 5 到 8，让房间通关、门和弹窗能跑通；最后做步骤 9 到 10，补文档和验证。这样后面你导入新地图模组时，只需要新增地图配置和资源映射，不需要再重构 `GameWorld`。
