# 多地图房间架构说明

## 目标

游戏地图按“房间关卡”组织。每张地图是一个独立房间，玩家在当前房间击杀足够数量的僵尸后，出口门开启。玩家靠近开启的门并按进入键后，加载目标房间，并按全新关卡重置玩法状态。

这套架构的重点不是一次性做完所有地图，而是让后续导入新地图模组时，只需要补地图配置和资源映射，不需要继续重构 `GameWorld`。

## 文件职责

- `src/game/map/types.ts`：定义地图、障碍物、门、出生点等配置类型。
- 后端 `maps` 表：保存所有可用地图的当前配置。
- 后端 `map_versions` 表：保存每次保存地图时产生的历史快照。
- `src/game/map/MapManager.ts`：负责地图加载、卸载、地图视觉对象、地图 collider、门状态和可进入门判断。
- `src/game/systems/GameWorld.ts`：负责游戏主循环、玩家、僵尸、子弹、掉落、HUD 数据和关卡重置，不直接写死具体地图内容。

## 地图配置结构

每张地图使用 `GameMapConfig`：

```ts
export type GameMapConfig = {
  id: string
  name: string
  spawnPoint: Vector3Tuple
  requiredKills: number
  groundMaterial?: GroundMaterialConfig
  colliders: readonly MapColliderConfig[]
  props: readonly MapPropConfig[]
  doors: readonly MapDoorConfig[]
}
```

字段含义：

- `id`：地图唯一标识，门和弹窗都用它切换地图。
- `name`：中文地图名，用于 HUD 和地图切换弹窗。
- `spawnPoint`：玩家进入该房间后的出生点。
- `requiredKills`：出口门开启需要的击杀数。
- `groundMaterial`：当前地图地板材质配置，包含 `textureId` 和 `repeat`；省略时使用默认石砖小图案材质。
- `colliders`：Rapier 静态 box collider 配置。
- `props`：地图视觉物配置。没有 `modelUrl` 时使用 box 占位物；有 `modelUrl` 时运行时会加载真实 GLB 模型，并用 `size` 作为模型归一化目标包围盒和 fallback 尺寸。
- `doors`：当前地图的出口门配置。

门使用 `MapDoorConfig`：

```ts
export type MapDoorConfig = {
  id: string
  position: Vector3Tuple
  size: Vector3Tuple
  targetMapId: string
  targetSpawnId: string
  interactionDistance: number
}
```

当前第一版只使用 `targetMapId` 切换地图，`targetSpawnId` 先作为后续多出生点扩展字段保留。

## 为什么地图配置和 `GameWorld` 分离

`GameWorld` 已经负责主循环、玩家移动、僵尸刷新、自动射击、掉落、碰撞伤害和 HUD 数据。如果再把地图模型、障碍物、门、地图列表也写进去，文件会越来越难维护。

现在的边界是：

- `GameWorld` 只知道“当前地图是什么”和“我要切换到哪张地图”。
- `MapManager` 知道地图对象怎么创建、旧地图怎么清理、门是否开启、玩家是否靠近门。
- 具体地图文件只描述地图内容，不写游戏流程逻辑。

这样后续新增地图时，主要改配置文件；后续改地图加载方式时，主要改 `MapManager`。

## 为什么地图模型和碰撞体分开维护

当前不从完整模型 mesh 自动生成碰撞体，原因是：

- 美术模型通常面数多，直接作为碰撞体性能不可控。
- 墓碑、树、围栏、墓穴等模型的视觉形状复杂，但玩法只需要大致阻挡范围。
- 手写 box collider 更容易调试，也方便用 `GAME_CONFIG.showPhysicsDebug` 看真实阻挡区域。

第一阶段规则：

- 模型或 `props` 只负责视觉。真实模型加载失败时会回退为 box，以保证地图仍可运行。
- `colliders` 负责物理阻挡。
- 小装饰物可以没有 collider。
- 墙、墓穴、大树、大石头、围栏等主要障碍物需要手写 collider。

## 通关和开门规则

当前房间通关条件是：

```text
当前击杀数 >= 当前地图 requiredKills
```

规则：

- 未通关时，出口门保持暗色，`MapManager.findEnterableDoor()` 不会返回可进入门。
- 通关后，出口门变为绿色并带轻微自发光。
- 玩家靠近已开启的门，并按 A/Space 时，进入目标地图。
- 地图切换弹窗不受通关限制，它是调试和演示入口。

## 地图切换时重置哪些状态

进入新房间按“完全新关卡”处理。

会重置：

- 玩家血量。
- 武器等级。
- 武器经验。
- 当前击杀数。
- 存活计时。
- 僵尸列表和僵尸物理体。
- 子弹列表。
- 掉落物。
- 僵尸刷新器。
- 门状态。

会切换：

- 当前地图配置。
- 地图视觉对象。
- 地图障碍物 collider。
- 玩家出生点。

暂时保留：

- 游戏视角模式。
- 当前控制器输入组件。

## 后续新增地图步骤

新增地图时建议按这个顺序：

1. 在编辑器中填写 `id`、`name`、`spawnPoint`、`requiredKills`。
2. 根据地图模型配置主要障碍物 `colliders`。
3. 配置临时 `props` 或后续真实模型资源映射。
4. 配置 `doors`，让上一张地图可以指向这张地图，这张地图也可以指回其他地图。
5. 点击“保存后端”把地图写入数据库。
6. 返回游戏或刷新页面，用地图弹窗确认新地图可以切换。
7. 打开物理调试线框时，检查 collider 和模型位置是否大致对齐。

## 当前限制

- 门还没有真实开门动画，只用占位盒子和材质状态表达。
- `targetSpawnId` 还没有实际多出生点查找逻辑，当前切图统一使用目标地图的 `spawnPoint`。
- 地图视觉物当前仍然是 box 占位，真实墓地模型加载会在后续资源接入步骤处理。
- 地图边界仍然使用 `GameWorld` 里的固定四面墙，后续如果每张地图大小不同，需要把边界也迁移进地图配置。
