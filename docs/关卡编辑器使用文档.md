# 关卡编辑器使用文档

## 定位

关卡编辑器是当前项目内的开发工具，用来摆放地图物件、配置碰撞体、设置玩家出生点、添加出口门，并导出可接入游戏的 `GameMapConfig` 配置。

它不是玩家可见功能，也不会进入 `zjj-virtual-arcade-controller` npm 包。第一版不接后端，不做在线保存，导出的配置需要开发者手动复制到 `src/game/map` 下的新地图文件中。

## 进入编辑器

启动项目后，在游戏顶部点击“编辑器”按钮进入编辑模式。进入编辑器后，游戏画布、HUD、虚拟摇杆和按钮会隐藏，避免和编辑操作冲突。

再次点击顶部“返回游戏”可以退出编辑器。

## 编辑器区域

编辑器分为三块：

- 左侧“对象库”：选择要放置的地图资源，并切换编辑模式。
- 中间“编辑视口”：Three.js 画布，用于放置、选中、拖拽物件，设置出生点和门。
- 右侧“地图设置”：编辑地图基础信息、选中对象、碰撞体、出口门和导出配置。

## 视口操作

编辑视口支持：

- 左键点击地面：根据当前模式放置对象、设置出生点或添加门。
- 左键点击对象或门：选中目标。
- 左键拖拽对象或门：移动选中目标。
- 滚轮：缩放镜头。
- 右键或触控板拖动：平移镜头。
- `W/A/S/D`：旋转镜头，`A/D` 左右环绕，`W/S` 调整俯仰。

拖拽对象时会保留鼠标命中点和对象中心之间的偏移，避免选中后对象中心突然跳到鼠标位置。

## 画布反馈

编辑视口底部状态栏会显示当前模式、当前选中目标、吸附状态、辅助线状态和主要操作提示。

选中对象时，对象会出现暖黄色高亮；选中出口门时，门会变亮。对象和门的高亮互斥，方便判断当前右侧属性面板正在编辑哪一类目标。

## 放置对象

1. 在左侧切换到“放置对象”。
2. 在对象库中选择资源。
3. 点击中间视口地面放置对象。
4. 放置后对象会自动选中，并出现在右侧对象列表里。

对象库会自动收集 `kenney_graveyard-kit_5.0` 里的 GLB 模型，目前包含墓地包的 91 个模型，并通过同名 `Previews/*.png` 显示预览图。

对象库支持按名称或资源 ID 搜索，也可以按资源分类筛选。筛选只影响左侧对象库显示，不会影响已经放置到地图里的对象。

为了减少编辑器首屏资源压力，左侧对象库默认只加载预览图。真实 GLB 模型会在放置资源、载入旧地图或保存前按需解析 URL，不会在编辑器打开时一次性加载全部模型。

编辑器和游戏运行时使用同一套 `assetId -> GLB` 资源映射。后端地图即使只保存 `assetId`、没有保存 `modelUrl`，编辑器载入时也会按资源 ID 懒加载真实模型；只有资源库里找不到该 `assetId`，并且对象本身也没有 `modelUrl` 时，才会显示占位方块。

资源卡片上的“默认碰撞体”表示该资源放置后会默认启用 collider。“仅视觉/灯光”表示默认不参与物理阻挡。默认值只是编辑器的初始建议，选中对象后仍然可以在右侧属性面板手动开启或关闭碰撞体。

地图对象现在只保留一套边界。加载 GLB 后，编辑器会用 `THREE.Box3` 计算模型真实可视包围盒；边界线、吸附和导出的 Rapier 静态碰撞体都使用这套包围盒，并会乘上对象缩放。模型还没加载完成时，会先用资源默认尺寸兜底。

这样做是为了让“看到的边界”和“实际导出的碰撞体”一致。个别素材如果因为模型空白或包围盒不规则出现轻微穿模，可以在右侧继续调整对象缩放、位置或碰撞体开关。

默认碰撞体规则大致如下：

- 墙、栅栏、墓穴、墓碑、棺材、柱子等结构或障碍物默认启用碰撞体。
- 蜡烛、灯笼、碎石、小细节、角色摆件、道路等装饰资源默认不启用碰撞体。
- 所有资源都会保留模型 URL 和预览 URL，保存后端时会写入地图配置。

## 编辑已有地图

左侧对象库顶部有“后端地图”选择框。点击“刷新”会从后端读取地图列表，选择地图后点击“载入”，编辑器会把数据库中的地图配置转换成可编辑状态。

载入后可以继续移动物件、调整 collider、修改出生点、编辑门和导出配置。点击“保存后端”会直接保存到后端数据库；“生成配置 / 复制配置”只作为调试和人工备份能力保留。

刷新、载入和保存后端地图时，编辑器会使用 Element Plus 消息提示反馈结果。手动刷新会提示当前读取到的地图数量；载入和保存成功会提示地图名称；接口异常时会弹出后端返回的错误信息，方便直接定位服务或数据问题。

载入后端地图时，画布可能会短暂出现透明代理盒，这是模型 URL 和 GLB 文件正在懒加载的中间状态。加载成功后会显示真实模型；加载失败或资源 ID 不存在时，编辑器会回退成普通方块，方便继续定位问题对象。

载入旧地图时，编辑器会用 `props` 还原可视物件，并尽量用相同位置或同名规则匹配 `colliders`。如果旧地图里有只写在 `colliders`、没有对应 `props` 的纯物理阻挡，它不会自动变成可编辑物件；这类配置建议后续补一个占位 `prop` 方便编辑。

## 吸附

中间视口顶部有“吸附”开关。开启后，放置或拖动物体时，会根据已启用的 box collider 自动吸附到附近物体周围。

当前吸附规则：

- 只影响开发编辑器，不会写入导出的地图配置。
- 只处理 X/Z 平面，Y 轴高度保持对象当前设置。
- 按对象边界线计算贴边位置，和导出的运行时碰撞体保持一致。
- 会生成类似 MC 方块放置的候选位置，包括左、右、前、后贴边位置和四个角位置。
- 当前物体会吸到离鼠标落点最近的合法候选位置。
- 旋转和缩放物体会先用边界线的世界轴向投影计算吸附范围。

## 边界线显示

顶部工具栏有“边界线”复选框，用来控制对象边界是否显示。

- 开启：显示黄色边界线，边界来自 GLB 模型加载后由 `THREE.Box3` 计算出的真实可视包围盒，并乘上对象缩放。
- 关闭：隐藏对象边界线。

这个复选框只影响视觉显示，不会修改对象的 `collider.enabled`。隐藏边界线后，物体仍然可以保留碰撞体，保存后端时也仍会导出运行时 Rapier collider。

## 编辑对象属性

选中对象后，右侧可以编辑：

- 对象基础信息：名称、资源 ID、删除当前对象。
- 对象位置 `X/Y/Z`
- `Y` 轴旋转
- 缩放 `X/Y/Z`
- 是否启用碰撞体
- 碰撞体位置 `X/Y/Z`
- 碰撞体尺寸 `X/Y/Z`

对象属性面板分为“对象 / 变换 / 碰撞体”三组。对象位置变化时，默认 collider 会跟随移动。对象旋转或缩放变化时，编辑器里的黄色边界线会同步变化，导出后的 Rapier 静态 box collider 也会使用同一份边界。

可以点击“删除选中对象”删除当前对象。

## 设置出生点

1. 左侧切换到“设置出生点”。
2. 点击中间视口地面。
3. 绿色标记会移动到新的出生点位置。
4. 右侧只在“设置出生点”模式下显示出生点 `X/Y/Z` 输入。

导出时，出生点会写入 `GameMapConfig.spawnPoint`。

## 添加出口门

1. 左侧切换到“添加门”。
2. 点击中间视口地面生成门。
3. 在右侧门列表中选中门。
4. 编辑目标地图 ID、目标出生点 ID、交互距离、位置和尺寸。

门会写入 `GameMapConfig.doors`。当前游戏逻辑中，玩家达到当前地图的开门击杀数后，靠近门并按 `A` 可以进入 `targetMapId` 指向的地图。

门属性面板分为“出口门 / 目标 / 位置和尺寸”三组。选中门时，右侧只显示当前门的编辑项，地图对象列表会暂时隐藏，减少误删或误改对象的概率。

可以点击“删除选中门”删除当前门。

## 地图基础信息

右侧地图设置包含：

- 地图 ID：导出配置中的 `id`，也会影响导出变量名。
- 地图名称：游戏 HUD 和地图弹窗中显示的名称。
- 开门击杀数：写入 `requiredKills`，控制门何时开启。
- 仅自己可编辑：保存为后端地图的 `editMode`。关闭时为 `public`，所有登录用户都可以编辑；开启时为 `private`，只有地图创建者和超管可以编辑。
- 地板材质：写入 `groundMaterial.textureId`，用于编辑器预览和游戏运行时地面。
- 地板平铺：写入 `groundMaterial.repeat`，控制地板贴图在整张地图里的重复次数。

## 地图边界

编辑器地面、编辑器网格和游戏运行地图共用 `GAME_CONFIG.mapRadius * 2` 作为地图尺寸。当前 `mapRadius` 为 `12`，所以编辑器和游戏里的有效地图宽度都是 `24`。

这个尺寸不要在编辑器里单独写死，否则会出现编辑模式能放到边界外，但进入游戏后被真实边界挡住或显示错位的问题。

## 场景材质

游戏和编辑器共用 `src/game/map/EnvironmentMaterials.ts` 里的环境材质。

- 地板材质选项维护在 `src/game/map/GroundMaterials.ts`，当前使用 `kenney_retro-textures-fantasy/PNG` 里的 `floor_*.png` 贴图。
- 每张地图可以保存自己的 `groundMaterial`，旧地图没有该字段时会回退到 `floor-stone-pattern-small-depth`。
- 门使用 `src/game/assets/models/textures/kenney_retro-textures-fantasy/PNG/door_metal_gate_lock.png`，运行时门和编辑器门共用同一张贴图。
- 贴图使用 `SRGBColorSpace` 和 `Nearest` 过滤，保持 Kenney retro 贴图的像素风。

## 导出配置

右侧底部提供：

- “生成配置”：把当前编辑器状态转换成 TypeScript 配置文本。
- “复制配置”：把生成的文本复制到剪贴板。
- 文本框：显示完整导出内容，也可以手动复制。

导出内容包含：

- `id`
- `name`
- `spawnPoint`
- `requiredKills`
- `colliders`
- `props`
- `doors`

启用 collider 的对象会进入 `colliders`。所有放置对象会进入 `props`，并保留 `assetId`、`modelUrl`、`position`、`size`、`rotation`、`scale` 和 `color`。

## 接回游戏

地图正式接入游戏不再新增本地地图文件。完成编辑后按下面步骤处理：

1. 点击“保存后端”写入数据库。
2. 点击左侧“刷新”，确认后端地图列表能看到新地图。
3. 返回游戏或刷新页面，地图弹窗会从后端重新读取地图。
4. 进入地图后检查模型、碰撞体、出生点和出口门。

“生成配置 / 复制配置”只作为调试和备份使用，不再作为正式地图接入流程。

## 后端保存

编辑器左侧“后端地图”区域可以从后端刷新和载入地图。顶部“保存”会把当前编辑器状态转换成 `GameMapConfig`，并通过 `/api/maps/{mapId}` 保存到后端。

顶部“新建”会清空当前编辑画布，并生成一个新的地图 ID 和默认地图名称。新建只创建本地编辑草稿，不会立刻写入数据库；确认地图 ID、名称、权限和地板材质后，再点击“保存”才会把新地图写入后端。

顶部“删除”会删除当前选择的后端地图。删除前会弹出 Element Plus 确认框；确认后调用后端 `DELETE /api/maps/{mapKey}`。删除只影响数据库里的地图记录，不会立刻清空当前画布，避免误删后本地未保存的编辑内容也一起丢失。

地图编辑权限不会写入 `GameMapConfig`，而是作为后端元数据单独保存。载入后端地图时，编辑器会同步回填“仅自己可编辑”开关，避免再次保存时把私有地图误改成公开编辑。

开发环境中，Vite 会把 `/api` 代理到本地 Go 服务 `http://127.0.0.1:8088`。部署到服务器后，建议用同域 `/api` 反代到 Go 服务，避免前端写死服务器地址。

编辑模式只读取后端地图，不会从本地地图文件兜底。数据库为空时，编辑器会提示后端暂无地图。

## 验证

每次新增或调整地图配置后，至少运行：

```bash
corepack pnpm run build
```

进入游戏后可以通过顶部“地图”弹窗切换到新地图，检查：

- 地图名称是否显示正确。
- 玩家出生点是否正确。
- 视觉模型是否加载。
- 主要障碍物 collider 是否生效。
- 击杀数达标后门是否开启。
- 靠近门按 `A` 是否能切换到目标地图。

## 当前限制

- 不支持在线保存。
- 不支持撤销/重做。
- 不支持多选、复制、粘贴。
- 不支持自动从复杂模型生成 mesh collider。
- 不支持地形雕刻。
- 不支持关卡脚本和事件系统。
- 导出配置不会自动写文件，需要开发者手动接回游戏。
- 目标出生点 ID 当前作为门配置字段保留，运行时切图仍使用目标地图的默认 `spawnPoint`。
