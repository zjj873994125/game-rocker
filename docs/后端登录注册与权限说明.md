# 后端登录注册与权限说明

## 当前结论

登录注册已经改为后端 Token 方案。前端不再用本地模拟用户列表作为账号来源，注册和登录都会请求 Go 后端，后端验证成功后签发 Bearer Token。

## 为什么使用 Token

账号密码和权限必须由后端保存和判断。浏览器本地只能保存登录凭证，不能保存可被信任的用户表或权限结果。

当前实现使用 HMAC-SHA256 Token：

- 登录或注册成功后返回 `token`、`expiresAt` 和 `user`。
- 前端把 token 保存到 `zjj-auth-token`。
- 前端请求后端接口时自动带上 `Authorization: Bearer <token>`。
- 后端从 token 中解析用户身份，再执行权限判断。

后续如果需要服务端主动踢下线、刷新 Token 或多端会话管理，可以再增加 `user_sessions` 表，把 token 标识落库。

## 接口

- `POST /api/auth/register`：注册账号。
- `POST /api/auth/login`：登录账号。
- `GET /api/auth/me`：读取当前登录用户，需要 Bearer Token。

注册请求：

```json
{
  "phone": "13800138000",
  "nickname": "测试玩家",
  "password": "123456"
}
```

登录请求：

```json
{
  "phone": "13800138000",
  "password": "123456"
}
```

响应：

```json
{
  "token": "header.payload.signature",
  "expiresAt": "2026-05-29T09:00:00Z",
  "user": {
    "id": 1,
    "phone": "13800138000",
    "nickname": "测试玩家",
    "role": "user",
    "status": "active"
  }
}
```

## 权限规则

- 游客可以读取地图和玩游戏。
- 游客不能新建、修改或删除地图。
- 登录用户可以新建地图。
- 登录用户可以编辑 `edit_mode = public` 的地图。
- `edit_mode = private` 的地图只有创建者和超管可以编辑。
- 超管可以编辑所有地图。

前端编辑器里的“仅自己可编辑”开关会保存 `edit_mode`。这个字段属于后端权限元数据，不属于运行时地图配置，游戏读取地图时不会用它决定玩法逻辑。

## 数据表

建表 SQL：

```text
server/migrations/002_create_users_and_map_permissions.sql
```

本次新增：

- `users`：用户账号表。
- `maps.owner_user_id`：地图创建者。
- `maps.edit_mode`：地图编辑范围，`public` 或 `private`。

## 配置

```bash
AUTH_TOKEN_SECRET=change-me-in-production
AUTH_TOKEN_TTL=168h
```

生产环境必须替换 `AUTH_TOKEN_SECRET`，不能使用示例值。
