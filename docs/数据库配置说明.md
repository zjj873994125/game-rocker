# 数据库配置说明

## 当前结论

后端 ORM 选用 GORM，数据库先按 MySQL 配置。GORM 在 Gin 项目里使用广，MySQL 驱动成熟，后续做地图、资源、用户、版本记录等 CRUD 会比较省事。

当前代码只增加数据库配置和连接初始化能力，不会默认切换现有地图存储。`DB_ENABLED=false` 时仍然使用本地 JSON 文件。

## 配置文件

示例文件在：

```text
server/configs/database.example.env
```

本地真实配置文件为：

```text
server/configs/database.local.env
```

后端启动时会自动读取 `database.local.env`。这个文件已经被 `.gitignore` 忽略，可以放真实账号和密码。`database.example.env` 只作为示例文件，不建议写真实密码。

如果 shell 里已经手动设置了同名环境变量，shell 中的值优先，`database.local.env` 不会覆盖它。

本地配置示例：

```bash
DB_ENABLED=true
DB_DRIVER=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_NAME=zjj_game
DB_USER=root
DB_PASSWORD=your_password
DB_CHARSET=utf8mb4
DB_PARSE_TIME=true
DB_LOC=Local
DB_MAX_IDLE_CONNS=10
DB_MAX_OPEN_CONNS=50
DB_CONN_MAX_LIFETIME=1h
```

## 配置字段

- `DB_ENABLED`：是否启用数据库连接。默认 `false`。
- `DB_DRIVER`：数据库驱动。当前只支持 `mysql`。
- `DB_HOST`：数据库地址。
- `DB_PORT`：数据库端口。
- `DB_NAME`：数据库名。
- `DB_USER`：数据库账号。
- `DB_PASSWORD`：数据库密码。
- `DB_CHARSET`：字符集，默认 `utf8mb4`。
- `DB_PARSE_TIME`：是否解析 MySQL 时间字段，默认 `true`。
- `DB_LOC`：时间位置，默认 `Local`。
- `DB_MAX_IDLE_CONNS`：最大空闲连接数。
- `DB_MAX_OPEN_CONNS`：最大打开连接数。
- `DB_CONN_MAX_LIFETIME`：连接最大生命周期。

## 后续落库步骤

## 地图数据表

第一版先落两张表：

- `maps`：当前地图主表，只保存当前有效配置。
- `map_versions`：地图历史版本表，每次保存地图时追加一条快照。

GORM 模型在：

```text
server/internal/domain/map.go
```

建表脚本在：

```text
server/migrations/001_create_maps.sql
```

`maps.config` 和 `map_versions.config` 使用 MySQL `JSON` 字段保存完整 `GameMapConfig`。这样第一版不用把 `groundMaterial`、`props`、`colliders`、`doors` 拆成多张子表，能先保持和前端地图配置一致。后续如果需要按资源、门、碰撞体或材质做复杂查询，再拆子表。

## 后续落库步骤

1. 给地图模块抽出 `Store` 接口。
2. 在 `internal/repository` 中新增 MySQL 地图仓储。
3. 在 `internal/app` 根据配置选择 `FileStore` 或 MySQL 仓储。
4. 保存地图时写入 `maps`，并追加写入 `map_versions`。
5. 前端游戏和编辑器统一通过 `/api/maps` 从数据库读取地图。
6. 用户、Token 登录和地图编辑权限已开始接入，详见 `docs/后端登录注册与权限说明.md`。

## 用户与地图权限表

用户表和地图权限字段脚本在：

```text
server/migrations/002_create_users_and_map_permissions.sql
```

本脚本新增 `users` 表，并给 `maps` 增加 `owner_user_id` 和 `edit_mode`。`edit_mode = public` 表示登录用户可编辑，`edit_mode = private` 表示只有地图创建者和超管可编辑。
